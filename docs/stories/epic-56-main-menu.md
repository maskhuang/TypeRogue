# Epic 56: 主菜单系统

## 背景

目前游戏启动后直接进入 demo overlay → 点击开始 → 职业选择 → 战斗。缺少正式的主菜单界面，玩家无法：
- 在不开始游戏的情况下调整设置（音量、语言、按键绑定等）
- 进入教程学习核心机制
- 看到游戏整体状态（解锁进度、Ascension 等级等）

同时蜕变师的解锁条件"解锁所有技能"过于苛刻且不可控，改为"用造词师通关一次"更合理，形成 无职业→造词师→蜕变师 的自然递进链。

## 设计目标

- **正式入口**：替代 demo-start-overlay，提供主菜单作为游戏的第一屏
- **渐进引导**：教程关让新手理解核心打字→得分→技能循环
- **可配置性**：设置面板管理音量、语言、显示等选项
- **解锁递进**：无职业(默认) → 造词师(首次通关) → 蜕变师(造词师通关)

## 游戏启动流程（改造后）

```
启动 → 主菜单
         ├─ 开始游戏 → 职业选择 → Ascension 选择 → 战斗循环
         ├─ 教程 → 教程关 → 完成后返回主菜单
         └─ 设置 → 设置面板 → 返回主菜单
```

### Story 56-2: 教程关设计

**范围：** 教程关卡的游戏设计文档

**设计方向（建议）：**
- [ ] **第 1 阶段：打字基础** — 显示词语，玩家打字，教"打完一个词=得分"
- [ ] **第 2 阶段：时间与目标** — 引入计时器和目标分数，教"达标过关"

- [ ] **第 4 阶段：商店** — 模拟商店界面，教"选技能、绑键位、开始下一关"
- [ ] **完成** — 恭喜文字 → 返回主菜单

**验收标准：**
- [ ] 输出教程关设计文档（关卡流程、每阶段目标、UI 提示文案）
- [ ] 设计评审通过

### Story 56-5: 蜕变师解锁条件变更

**范围：** 修改蜕变师解锁逻辑

**当前逻辑：**
```
造词师：首次通关（任意职业） ← 保持不变
蜕变师：解锁所有技能 ← 改掉
```

**新逻辑：**
```
造词师：首次通关（任意职业） ← 保持
蜕变师：用造词师通关一次 ← 新条件
```

**改动点：**
- [ ] `MetaState.checkProgressionUnlocks()` — 蜕变师条件从 `unlockedSkills.size >= totalSkillCount` 改为 `victoriedClasses.has('wordsmith')`
- [ ] 职业选择锁定提示文案更新：`🔒 用造词师通关一次解锁`
- [ ] i18n 双语更新
- [ ] 教程/提示文案同步（如有）

**验收标准：**
- [ ] 用造词师通关后蜕变师解锁
- [ ] 用无职业或蜕变师通关不解锁蜕变师
- [ ] 锁定提示文案正确显示

## 依赖与风险

| 风险 | 缓解 |
|------|------|
| 教程设计复杂度 | 56-2 先出设计文档，评审后再实现 |
| 战斗结束流程改动大 | 56-6 在最后整合，前面的 Story 可独立开发 |
| 设置面板与战斗中的冲突 | 初期仅在主菜单/商店可用，战斗中不开放 |
| 存档兼容性（蜕变师解锁条件） | 56-5 只改检查逻辑，已解锁的不会被锁回 |

## 工作量估计

- Story 56-1: M（主菜单 UI + 启动流程初步改造）
- Story 56-2: S（纯设计文档）
- Story 56-3: L（教程状态机 + HUD 覆盖 + 预设数据）
- Story 56-4: M（设置面板 UI + 音量/语言/显示控制）
- Story 56-5: S（条件改一行 + 文案更新）
- Story 56-6: M（流程串联 + 边界处理）

## 解锁递进链（完整）

```
首次启动 → 无职业（默认可用）
         ↓ 首次通关
       造词师 解锁
         ↓ 造词师通关
       蜕变师 解锁
         ↓ 三职业均通关
       无尽模式 解锁
```
