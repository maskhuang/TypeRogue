# Epic 34: 技能词条化重构（方案 B）

## 背景

当前技能系统存在核心问题：
- **乘算泛滥**：乘算产出者和乘算转化者独占键位，数值膨胀太容易（旧系统 4 层乘算叠加 → ×18.7 倍基础值）
- **加算重复**：加算产出者只有 7 个（每种资源 1 个），数值不同但机制完全相同，缺乏选择深度
- **乘算不受控**：乘算技能作为独立技能随意购买，没有稀缺性约束

## 采用方案：方案 B — 挪动 + 扩充

**核心思路：**
1. 所有产出者出生都是加算的
2. 新增 5 种有趣的加算机制（蓄力/衰减/脉冲/暴击/虚无），每种 × 7 资源 = 35 个新产出者
3. 乘算类产出者和乘算类转化者移入附魔系统 —— 附魔可以将加算技能变为乘算
4. 乘算数量 = 获得的「乘算化」附魔数量，天然稀缺

**不动的部分：**
- Connector / Replicator / Amplifier 保持不变
- add 类 Converter 保持不变
- 附魔系统保留并扩充

**设计文档：** `docs/design/affix-skill-system.md`（方案 A/B 对比及完整数值表）

## 核心数字

| 指标 | 重构前 | 重构后 |
|------|-------|-------|
| 加算产出者 | 7 个 | 42 个（7 原版 + 35 新机制） |
| 乘算产出者 | 7 个（独立技能） | 0 个（移入附魔） |
| 乘算转化者 | 37 个（独立技能） | 0 个（移入附魔） |
| 加算转化者 | 37 个 | 37 个（不变） |
| 附魔种类 | 35 个 | 36 个（+1 乘算化附魔） |
| 新机制类型 | 0 | 5（蓄力/衰减/脉冲/暴击/虚无） |

## Stories

### Story 34.1: 新增加算产出者（5 种机制 × 7 资源）

**复杂度: High**
**依赖: 无**

新增 35 个加算产出者，每种使用独特的触发机制。所有产出者都是加算的，通过机制差异化而非数值差异化提供选择深度。

**5 种新机制：**

| 机制 | 效果 | 状态生命周期 |
|------|------|------------|
| 蓄力 | 未触发时每秒积攒 +8% 产出，触发时释放并清零，上限 200% | 实时（触发清零） |
| 衰减 | 首次产出 ×2，每次触发 -15%，下限 ×0.5，每词重置 | 每词重置 |
| 脉冲 | 每第 4 次触发产出 ×3，其余正常 | 每关重置 |
| 暴击 | 50% 概率产出 ×2 | 无状态 |
| 虚无 | [PositionRelation]范围内每空位 +X% 产出 | 实时计算 |

**验收标准：**
- AC1: 在 `data/producers.ts` 中定义 35 个新产出者（5 机制 × 7 资源），使用现有 `baseValues` 作为基础值
- AC2: 蓄力产出者 — 每秒积攒 +8%（上限 200%），触发时释放全部蓄力并清零；战斗 tick 中更新蓄力值
- AC3: 衰减产出者 — 首次触发 ×2.0，每次触发后 -0.15，下限 0.5；每个新词重置为 2.0
- AC4: 脉冲产出者 — 维护 triggerCount，每第 4 次触发 ×3.0；每关重置计数
- AC5: 暴击产出者 — 每次触发 50% 概率 ×2.0
- AC6: 虚无产出者 — 每种资源有 6 个变体（6 种 PositionRelation），使用 `keyboardTopology.ts` 计算空位数，按现有 Repulsion 附魔的 bonusPerSlot 值（Adjacent 25%、SameRow 10%、SameColumn 30%、SameHand 5%、SameFinger 35%、Symmetric 50%）
- AC7: `SkillRuntimeState` 新增字段：`chargeAccumulated`、`currentDecayMult`、`triggerCount`（复用或扩展现有 `GameState`）
- AC8: `triggerProducer()` 中按产出者机制类型分支计算，新机制的乘算效果在基础加算值之上应用
- AC9: 新产出者正确触发视觉反馈（`showTriggerPopup` / `showFeedback`）和音效（`emitResourceSound`）

**估点：** 8

### Story 34.2: 乘算产出者移入附魔系统

**复杂度: High**
**依赖: 34.1**

将 7 个乘算产出者从独立技能移入附魔系统，作为「乘算化」附魔。附魔后将加算产出者的运算符从 add 改为 multiply。

**乘算化映射表：**

| 资源 | 加算基础值 (Lv1/2/3) | 乘算化后 (Lv1/2/3) |
|------|---------------------|-------------------|
| base | +5/8/12 | ×2.0/2.3/2.6 |
| score | +15/24/36 | ×1.1/1.15/1.2 |
| multiplier | +0.2/0.32/0.48 | ×1.15/1.2/1.25 |
| time | +0.2/0.32/0.48 | ×1.02/1.025/1.03 |
| gold | +3/5/8 | ×1.3/1.5/1.7 |
| fragment | +1/1.6/2.4 | ×1.8/2.1/2.4 |
| mutagen | +1/1.6/2.4 | ×1.8/2.1/2.4 |

**验收标准：**
- AC1: 在 `data/enchantments.ts` 新增 `ench_multiply` 附魔定义（1 个通用附魔，附上后根据技能资源类型查表映射乘算值）
- AC2: `ENCHANTMENTS` 和 `EnchantmentDefinition` 类型扩展支持 `category: 'operator'` 和 `multiplyValues` 字段
- AC3: 附魔后产出者的 `operator` 从 `'add'` 变为 `'multiply'`，`triggerProducer()` 中使用乘算路径
- AC4: 乘算化后的新机制产出者保留原有机制（蓄力/衰减/脉冲/暴击/虚无），仅运算符改变
- AC5: 从 `PRODUCERS` 中删除 7 个旧乘算产出者（prod_focus / prod_crit / prod_frenzy / prod_eternal / prod_treasury / prod_refine / prod_mutagen_surge），加入 `DELETED_SKILL_IDS` 确保存档兼容
- AC6: `drawEnchantmentPair()` 可抽到乘算化附魔，权重与其他附魔持平
- AC7: 附魔 UI 正确显示乘算化状态（图标/描述更新）

**估点：** 5

### Story 34.3: 移除乘算转化者

**复杂度: Medium**
**依赖: 34.2**

删除所有 37 个 multiply 类转化者，仅保留 37 个 add 类。乘算化附魔同样适用于转化者 —— 将 `formula: 'add'` 变为 `formula: 'multiply'`。

**验收标准：**
- AC1: 从 `CONVERTERS` 中删除所有 `formula: 'multiply'` 的转化者（37 个），ID 加入 `DELETED_SKILL_IDS`
- AC2: `drawConverterPool()` 从剩余 37 个 add 转化者中抽取（调整抽取数量：从 31 改为合适数量）
- AC3: 乘算化附魔可附加到转化者上，将 `formula` 从 `'add'` 改为 `'multiply'`，k 值从 add 映射到 multiply（使用预定义的转换表）
- AC4: 转化者乘算化后的 k 值映射表，确保各源→目标组合数值合理（参考旧乘算转化者数值）
- AC5: 存档加载时过滤 `DELETED_SKILL_IDS`，玩家已持有的乘算转化者静默移除
- AC6: 商店/技能列表 UI 不再显示已删除的乘算转化者

**估点：** 3

---

### Story 34.4: 转化/衍生词条支持同源资源

**复杂度: Medium**
**依赖: 34.1**

当前转化者的源资源和衍生附魔的额外资源不能选本技能资源。解除此限制：
- 同源转化 = 读自己的资源值加算回自己（等效指数增长）
- 同资源衍生 = 额外产出同种资源（等效百分比增幅）

**验收标准：**
- AC1: add 类转化者允许 source === target（例：score 转化者读取 resources.score 加算回 score）
- AC2: 同源转化者使用独立调低的 k 值（参考设计文档 k 值校准表），防止指数增长过快
- AC3: 衍生附魔的 `extraResource` 允许等于被附魔技能的资源类型（等效产出 ×(1+ratio)）
- AC4: 同源转化者在商店池中的权重独立调低（权重 3 vs 异源 10），通过 `drawConverterPool` 抽取逻辑实现
- AC5: 同源转化者数据定义：每种资源 1 个，共 7 个新 add 转化者加入 `CONVERTERS`
- AC6: 同源转化者 k 值按资源校准：base 0.02~0.05、score 0.0005~0.001、multiplier 0.10~0.25、time 0.01~0.025、gold 0.003~0.008、fragment/mutagen 0.02~0.05
- AC7: 转化者源值读取定义统一：base=词内累积、score=关卡累积(resources.score)、multiplier=当前倍率、time=剩余秒数、gold=当前持有、fragment/mutagen=本关产出(classResourceProduced)

**估点：** 3

### Story 34.5: 商店/技能池再平衡

**复杂度: Medium**
**依赖: 34.1, 34.2, 34.3**

产出者池从 14 个变为 42 个（原 7 加算 + 35 新机制），转化者池从 74 个变为 44 个（37 add + 7 同源）。商店刷出逻辑和技能池抽取需要重新平衡。

**验收标准：**
- AC1: 产出者池抽取逻辑适配 42 个产出者，按机制类型分组加权（原版/蓄力/衰减/脉冲/暴击/虚无各组权重可调）
- AC2: 虚无产出者按 PositionRelation 分为 6 个变体，每种资源 6 个虚无变体 → 42 个虚无产出者独立参与抽取（权重调高）
- AC3: 商店每次刷新展示的技能数量和品类分布合理（不全是同一机制）
- AC4: 转化者池抽取数量从 31 调整为适合 44 个 add 转化者的数量
- AC5: 附魔抽取池包含乘算化附魔，权重与空间型附魔持平
- AC6: 职业资源产出者（fragment/mutagen）仅对应职业可见，与现有 ClassResourceFilter 逻辑一致

**估点：** 3

### Story 34.6: UI 更新 — 附魔与新机制展示

**复杂度: Medium**
**依赖: 34.2**

更新技能 UI 以展示新机制状态和乘算化附魔效果。

**验收标准：**
- AC1: 键盘可视化中，被乘算化附魔的技能显示特殊边框/光效，区分加算和乘算技能
- AC2: 技能描述面板显示机制类型标签（蓄力/衰减/脉冲/暴击/虚无）
- AC3: 蓄力产出者在键盘可视化中显示当前蓄力百分比（充能条或数字）
- AC4: 衰减产出者显示当前衰减倍率
- AC5: 脉冲产出者显示触发计数（当前第 N/4 次）
- AC6: 暴击触发时有特殊视觉反馈（闪光/放大效果）
- AC7: 虚无产出者在键盘上高亮显示空位范围

**估点：** 5

### Story 34.7: 数值平衡与调优

**复杂度: Medium**
**依赖: 34.1, 34.2, 34.3, 34.4, 34.5**

全流程数值验证和调优，确保新系统在各关卡阶段表现合理。

**验收标准：**
- AC1: 标准关（30s）无乘算附魔时，目标分数可达成（验证前 3 关）
- AC2: 精英关/Boss 关在合理技能配置下可通关
- AC3: 乘算化附魔数量控制验证：平均一局获得 2-3 个乘算化附魔，不超过 5 个
- AC4: 同源转化者在 Boss 关（60s，高频字母 50-60 次触发）的累积产出不超过基础值的 ×10
- AC5: 新机制产出者在中期（4-6 关）的平均产出与原版加算产出者差距在 ±50% 以内
- AC6: 蓄力产出者在低频键位（Z/Q/X）上的表现合理（长时间蓄力 → 高爆发）
- AC7: 衰减产出者在高频键位（E/T/A）上的表现合理（快速衰减到下限）
- AC8: 根据测试结果调整各机制数值参数（蓄力速率/衰减速率/脉冲间隔/暴击概率等）

**估点：** 3

## 依赖关系

```
34.1 新增加算产出者
 ├── 34.2 乘算移入附魔 ──→ 34.3 移除乘算转化者 ──┐
 ├── 34.4 同源转化/衍生                           ├── 34.5 商店池再平衡
 └── 34.6 UI 更新                                │
                                                  └── 34.7 数值平衡调优
```

34.1 是基础，完成后 34.2/34.4/34.6 可并行。34.5 和 34.7 需要前置全部完成。

## 实施顺序

```
Phase 1: 34.1 新机制产出者 (8pt)     ← 核心，最先开发
Phase 2: 34.2 乘算→附魔 (5pt)        ← 改变乘算分布
         34.4 同源转化/衍生 (3pt)     ← 可并行
         34.6 UI 更新 (5pt)           ← 可并行
Phase 3: 34.3 移除乘算转化者 (3pt)    ← 依赖 34.2
Phase 4: 34.5 商店池再平衡 (3pt)      ← 依赖 Phase 1-3
Phase 5: 34.7 数值平衡调优 (3pt)      ← 最终调优

总计 30 点
```

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 新机制产出者数值不平衡 | 某些机制过强/过弱 | 34.7 专门调优，参数可配置 |
| 乘算化附魔获取频率不当 | 乘算太多或太少 | 通过附魔权重和抽取逻辑控制 |
| 旧存档兼容性 | 已持有乘算技能的存档崩溃 | DELETED_SKILL_IDS 过滤 + 静默移除 |
| 虚无产出者变体过多（42 个） | 商店被虚无淹没 | 按机制分组加权抽取 |
